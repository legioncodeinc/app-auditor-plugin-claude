# Produce character and scene videos

1. Establish the deliverable: shot intent, cast, visual style, duration, framing, reference roles, and sound. Ask only for missing details that change the shot. Use an approved supplied character reference when appearance must persist.
2. Read the guide for the selected model, then inspect its tool schema. These seven endpoints differ in media types, duration, audio, and framing. Do not copy inputs between tools.
3. Build a concise shot brief: character identity and wardrobe; scene and light; starting pose; primary action in causal order; camera; ending pose; sound. For multi-character scenes, distinguish each subject's position and actions. For a music video, assign each shot's action to the intended musical beat, without promising exact synchronization.
4. Assign file roles. Upload every reference with replicate_upload_file and use returned file IDs, or use path wrappers and let the generation tool invoke the same uploader. Images may define identity, first/last frame, or environment; videos may define motion or editing source; audio may define rhythm or voice only where supported. Keep the reference indexing order stable.
5. Confirm that the requested generation falls within the user's approved spend and external-upload scope. A request to write this server is not permission to run a paid generation. When generation itself is approved, choose one model-specific tool and a unique request_key.
6. Capture prediction_id immediately. Poll replicate_get_prediction at the suggested interval. Never regenerate to check progress. If the response is uncertain, reuse the same request_key and arguments; an unresolved ledger entry requires inspection of provider history before another submission.
7. Inspect the resulting clip. Check character shape, fingers/limbs, face and costume continuity, object permanence, camera motion, causal timing, dialogue and audio. Match it against the user's shot brief. Change one direction at a time for a separately authorized take.
8. Return the actual output link, prediction ID, model, settings, and any observed artifact. Replicate output links are temporary; save media through the user's already authorized workflow. Cancellation changes the remote job and must be requested.

Model limits and API facts: [distillation](../references/research/distilled-replicate-video.md), [HTTP OpenAPI](../references/research/raw/replicate-http-openapi.json). Creative direction is author guidance, not a tested quality guarantee. This skill focuses on characters, scenes, performances, animation and music-video shots.
