## Findings that determine implementation

- Wan: prompt required, optional first image, 2-30 seconds, 480p/720p/1080p, optional negative prompt/prompt expansion/seed. Image framing supersedes requested ratio. Image <=10MB; seed range is prose-defined 0-2147483647. [card](raw/alibaba--wan-3.md), [schema](raw/alibaba--wan-3--schema.json).
- Runway: prompt required, optional image, duration enum exactly 5 or 10, six ratio choices, optional seed. There is no resolution or audio input. The README calls image-to-video a future capability while the current input schema already includes image; use the current input schema for this wrapper and flag the README as stale on that point. [card](raw/runwayml--gen-4.5.md), [schema](raw/runwayml--gen-4.5--schema.json).
- Veo: prompt required, duration 4/6/8, resolution 720p/1080p, audio toggle, first/last image, 1-3 reference images, negative prompt, seed. References require 16:9 and 8 seconds. The card says last_frame is ignored with references; the wrapper refuses that combination to prevent silently discarded direction. [card](raw/google--veo-3.1.md), [schema](raw/google--veo-3.1--schema.json).
- Seedance 2.0: required prompt <=4000 characters, up to 9/3/3 image/video/audio references, video total and audio total each <=15 seconds. Audio references need image or video references. First/last frames cannot mix with reference images. Schema duration is integer -1 through 15; the source does not disambiguate 0 or every small integer, so no extra minimum is invented. Schema resolution includes 1080p/4k while the README resolution table only lists 480p/720p; the current schema governs accepted fields. [card](raw/bytedance--seedance-2.0.md), [schema](raw/bytedance--seedance-2.0--schema.json).
- Seedance 2.5: prompt optional with visual media, references up to 30/10/10, video total and audio total each <=30 seconds. Duration 4-30 or -1 per README; schema's coarse -1..30 bounds alone also admit 0-3, so the wrapper uses the documented valid durations. Frames conflict with all reference collections. Frames/edit/extend require adaptive framing; editing needs -1. Output is mp4/mov and resolution only 480p/720p. Wrapper workflow selects generate/edit/extend and is not a provider parameter. [card](raw/bytedance--seedance-2.5.md), [schema](raw/bytedance--seedance-2.5--schema.json).
- Kling: required prompt, optional negative prompt, both <=2500 characters per prose; duration 3-15, standard/pro/4k modes; start/end JPEG/PNG <=10MB and minimum 300px, starting ratio 0.4..2.5. End requires start. multi_prompt is a JSON-encoded string containing up to six prompt/duration shots, minimum 1 second per shot and exact duration sum. The older README describes a 1080p maximum and only standard/pro modes; the current schema also includes 4k, which governs this wrapper. [card](raw/kwaivgi--kling-v3-video.md), [schema](raw/kwaivgi--kling-v3-video--schema.json).
- Grok: required prompt, optional image or editing video <=8.7 seconds; generation 1-15 seconds, 480p/720p. Duration/ratio/resolution are ignored for editing, so wrapper refuses them in editing mode. The README discusses Normal/Fun/Custom modes but there is no such input in the current schema. Native audio has no on/off parameter. [card](raw/xai--grok-imagine-video.md), [schema](raw/xai--grok-imagine-video--schema.json).

## HTTP and file contracts

- Official-model prediction creation is POST /v1/models/{owner}/{model}/predictions with a JSON input object. Read/cancel use the prediction ID endpoints. File creation is POST /v1/files with multipart content; the payload is less than 100MB. File results include ID, expiry, size, checksum, content type, and urls.get. [OpenAPI](raw/replicate-http-openapi.json), [provenance](raw/replicate-http-openapi.json.source.md).
- The official JavaScript client's file transform passes the returned file.urls.get to prediction inputs. Do not synthesize a download URL or accidentally forward the API token to a delivery domain. [file client](raw/replicate-files-client.js), [input transform](raw/replicate-js-util.js).
- MCP stdio is newline-delimited JSON-RPC, with stdout reserved for protocol messages. Tools declare input schema, annotations, and content/structuredContent. Tool execution failures use isError, while invalid JSON-RPC envelopes/unknown methods use JSON-RPC errors. Initialization negotiates a supported version before normal operation. [transports](raw/mcp-transports.md), [tools](raw/mcp-tools.md), [lifecycle](raw/mcp-lifecycle.md).

## Design decisions, not vendor claims

Separate tool names target fixed allowlisted model endpoints. Every media reference uses a local upload or a server-issued file ID. Inspect local bytes using ffprobe before upload, enforce file roots and reference limits, and compare live model inputs before a paid create call. Store request-key outcomes in a local SQLite ledger to prevent repeat prediction POSTs across restarts; pending submissions stay unresolved rather than being retried. Refuse schema drift until reviewed. These are wrapper policies; they do not promise provider idempotency, identical seeds, exact lip sync, or cross-shot identity guarantees.

Creative recommendations in the guides are author recommendations grounded in the model capabilities above, not measured quality rankings. Each guide includes the exact field table and a model-specific example. No live prediction, upload, charge, or quality benchmark was performed during this build.

## Authenticated API verification during approved activation

Read-only authenticated checks confirmed access to all seven named models. The API represents enum fields with a single-member allOf containing a generic "An enumeration." description; the public cards flatten that wrapper and use the field's substantive description. Nullable optional fields may also carry explicit default:null in the API while the cards omit it. The current API versions differ from the card versions, but normalized input constraints match all seven cards. Evidence: [alibaba/wan-3](raw/alibaba--wan-3--authenticated-input.json), [bytedance/seedance-2.0](raw/bytedance--seedance-2.0--authenticated-input.json), [bytedance/seedance-2.5](raw/bytedance--seedance-2.5--authenticated-input.json), [google/veo-3.1](raw/google--veo-3.1--authenticated-input.json), [kwaivgi/kling-v3-video](raw/kwaivgi--kling-v3-video--authenticated-input.json), [runwayml/gen-4.5](raw/runwayml--gen-4.5--authenticated-input.json), [xai/grok-imagine-video](raw/xai--grok-imagine-video--authenticated-input.json).

The server normalizes only those observed encoding differences, preserves substantive descriptions and constraints, and compares canonical JSON so boolean and integer values remain distinct. Conflicting or multiple allOf constraints remain visible. Real enum, range, required-field, meaningful-default or field-description changes still block generation. This correction prevents superficial API/card encoding differences from disabling paid generation; it does not remove the drift gate.
